# Steward

Tasks, notes and calendar in one installable web app. Works offline; syncs through the owner's own Google Drive and Google Calendar.

- Open https://csmit595.github.io/steward/ in Chrome and choose "Install".
- No build step: plain HTML, CSS and JavaScript modules.
- No data is stored in this repository. Everything a person enters stays on their device and in their own Google Drive ("Steward" folder).
- 4.4: Claude, online. Haiku (claude-haiku-5-5) refines each organizer suggestion once typing pauses ("Suggested · by Claude"); Sonnet (claude-sonnet-5-5) powers **Plan with Claude** on Today (an order and start times that never cover fixed blocks, what to move, which customers to tell early; nothing changes until "Use these times") and **Ask Claude** in Writing (More ▾). js/ai.js. Steward never holds the API key: Settings → Claude sends it once to the Steward helper, which keeps it in its script properties, adds it to each request (`ai` action) and counts the month's cost. No signal, no key or any error → the on-device organizer, as before. Shared setting `aiOn`.
- 4.3: organizes new tasks and notes. As a task or note is written, a "Suggested" row offers an area (CS Outdoors, Seminary, Church, Home/Family, Personal), finer tags (Embrace English, Sunday School, SCH 601, house project…), "customer promise" (the `promise` label), and a project or notebook; nothing is filed until **Confirm** is pressed (Add task, task details, the note editor). js/organize-core.js does the thinking with no browser APIs: public rules, a naive Bayes model trained on his confirmations ("lessons", including suggestions he took off), and the closest past lessons by meaning from the on-device MiniLM model (js/semantic.js). Lessons and "names and words it knows" (`orgwords`, personal names kept out of this public code) sync as Steward/steward-organize.json, and every device retrains from the same file, so the phone and the Mac suggest the same things. Settings → Organize automatically. Claude can add a known word with `{"op":"upsert","type":"orgword","item":{"word":"…","area":"home-family","tags":["…"]}}` (the app applies it; the helper leaves it for the app).
- 4.2: dictation works with no signal. Steward carries its own speech model (OpenAI's open Whisper, base English, about 77 MB, in vendor/models/Xenova/whisper-base.en) and runs it on the device in a background worker (js/whisper-worker.js); js/listen-device.js listens through the microphone, cuts speech into phrases at natural pauses and sends each to the model. Settings → Speak instead of type: Automatic (Chrome's speech service with signal, the device model without, switching over mid-dictation if the signal drops) or Always on this device (private). The model downloads by itself the first time a device is on Wi-Fi (a Mac any time), or with the button there or Download everything.
- 4.1: dictation. Speak tasks (microphone in Add task, the D key, or press and hold the plus button on the phone): "priority one", "project Hanel", "customer promise", "deadline Friday" and "8 a.m." are understood, "next task" adds it and starts another, "that's all" adds the last one and stops. Speak notes (microphone at the top of a note, or press and hold the plus): "period", "comma", "question mark", "new line" and "new paragraph" become punctuation, and an untitled note gets its first words as a title. Writing's Dictate uses the same engine. Needs Chrome; with no signal it uses Chrome's on-device speech model where the device has one.
- 4.0: signs in to Google with per-file Drive access only (no warning screen, no Google review needed). Calendar, notifications, and Claude's change files and scans come through the Steward helper's web app.
- 4.0.2 (with 4.0.1): Steward is now allowed to reach its helper (4.0.0's own security rule blocked it, which stopped every sync once the helper was connected); if the helper ever cannot be reached, tasks and notes still sync and Settings says what is waiting.
- 3.10.4: signing in to Google again is dependable. Steward says so plainly when a box on Google's screen was left unticked (and asks again instead of reusing a pass that cannot work), when the Google account picked has no Steward folder, or when the browser blocked Google's window; a sign-in window that never comes back can no longer freeze syncing; a device can no longer be left asking for a client ID.
- 3.9: reminders arrive as Steward's own notifications on the phone and the Mac, even while Steward is closed. The Google helper checks every minute and sends them by Web Push (no Google Calendar). Settings → Reminders turns them on per device; each device gets a test notification first, and the old "Steward Reminders" calendar stays as a backup until every device has shown its test, then it is emptied.
- 3.8: works fully with no signal. The tools (PDF reader, Word tools, page reader, search model) are kept in their own cache that survives updates; every attachment is kept on the device after each sync (Settings → Use with no signal, which also has "Download everything to this device").
- 3.7: updates without reinstalling. Settings → Updates has "Check for updates now" and "Reload Steward fresh" (re-downloads the app, keeps all data); a notice shows after each update; icon links carry a version so Chrome offers to update the installed icon when the artwork changes.
- 3.6: on the phone, swipe a note right to delete it (it goes to the trash); an Undo button shows at the bottom of the screen for 3 seconds.
- 3.5: on the phone, swipe the plus button left to add a task (two quick haptic clicks, and it turns into "Add task"); a tap still starts a note. The plus now shows on Calendar and Settings too.
- 3.4: on the phone the plus button starts a new note; inside a note it adds from the camera, photos or files; notes have a Share button.
- 3.3 was a full quality pass (date reading, sync safety, phone layout); see the commit notes.
- Background sync (3.2): when installed from Chrome (Android, or Mac with Chrome running), the service worker syncs with Drive every so often while Steward is closed — Claude's task changes, phone reminders, and calendar. Chrome decides how often. Changes made with no signal are sent once the connection returns.
